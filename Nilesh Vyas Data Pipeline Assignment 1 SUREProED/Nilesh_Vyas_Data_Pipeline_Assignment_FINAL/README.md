## 1\. Selected Source

### E-commerce Sales System

For this assignment, I selected an e-commerce sales system as the single real-world data source.

The source produces sales/order data such as:

* Order ID
* Customer ID
* Product
* Quantity
* Price
* Order Date
* Location

The goal is to move this data through a simple pipeline so that it can be cleaned, stored and used for business reporting.

## 4\. Component Explanation

|Component|Why it exists|
|-|-|
|E-commerce Sales Data|Source where the sales data is generated or obtained.|
|Python Ingestion|Reads the incoming sales files and moves the data into the pipeline.|
|Cloud Storage|Stores the raw sales files before transformation.|
|Dataflow|Cleans and transforms the data, such as handling duplicates, missing values and data types.|
|BigQuery|Stores the processed data for analytical queries and reporting.|
|Looker Studio|Allows business users to view the processed data through dashboards and reports.|

## 5\. What Happens to the Data?

1. Sales data is generated by the e-commerce system and made available as CSV/Excel files.
2. Python reads the incoming file and starts the ingestion process.
3. The raw file is stored in Cloud Storage so the original data is retained.
4. Dataflow processes the data by cleaning, filtering and transforming it.
5. The processed data is loaded into BigQuery for analytical storage and querying.
6. Looker Studio uses the processed data to create dashboards and reports.

## 6\. Why Does the Data Move from One Component to the Next?

The data first enters through the ingestion stage because the pipeline needs a way to receive the source data.

The raw data is then stored so that the original input is available before transformation.

The data moves to processing because raw sales data may contain duplicates, missing values or inconsistent formats.

After processing, the clean data moves to BigQuery because it needs to be queried and analyzed efficiently.

Finally, the processed data moves to the consumer layer so business users can understand sales performance through reports and dashboards.

## 8\. Pipeline Type

This is a **batch-oriented data pipeline** because the sales files can be collected and processed periodically rather than processing every individual record immediately.

## 9\. Short Architecture Explanation

The pipeline follows the basic idea:

**Source → Movement → Processing → Storage → Usage**

The design is intentionally simple. Each component has a specific purpose and the data moves forward because the next stage performs a different required function.
